## Code mein kya likha gaya (samjhein)

```python
def get_baseline_models():
    return {
        "Majority Class": DummyClassifier(strategy='most_frequent'),
        "Logistic Regression": LogisticRegression(max_iter=1000, random_state=42),
        "Decision Tree": DecisionTreeClassifier(random_state=42),
        "Random Forest": RandomForestClassifier(random_state=42)
    }
```

**Ye ek "dictionary" hai** — Python mein ye jaise ek **naamzad dabba (labeled box)** hota hai. Har "naam" (jaise "Majority Class") ke sath ek "cheez" (jaise `DummyClassifier(...)`) judi hui hai. Jab hum `"Majority Class"` likhenge, Python humein wo khaas model de dega.

**`DummyClassifier(strategy='most_frequent')`** — ye hamara sabse "bewakoof" model hai, jo hamesha "most frequent" (sabse zyada aane wali) value bol deta hai (yaad hai, "No churn" 73.5% hai, isliye ye hamesha "No" bolega).

**`random_state=42`** — ye **bohat zaroori** hai. ML models mein kahin kahin "random" cheezein hoti hain (jaise Decision Tree kaise banta hai shuru mein). `random_state=42` ka matlab hai "har dafa **wahi** random choices karo" — taake agar aap code dobara chalayen, **wahi natija** aaye. Agar ye na likhen, to har baar thora alag result aayega, jo confusing hota.

## Ab asal numbers samjhte hain

### Accuracy (5 folds)
```
Fold 1: 0.8305   Fold 2: 0.8021   Fold 3: 0.8057   Fold 4: 0.7915   Fold 5: 0.7913
Mean: 0.8042
```

**Matlab:** Har fold mein model ne taqreeban **80%** predictions sahi kin. Lekin yaad rakhein — humara **Majority Class baseline** (hamesha "No" bolne wala) bhi **73.5% accuracy** le leta. Matlab Logistic Regression ne sirf **~7% behtar** kiya accuracy mein — zyada dramatic nahi, lekin positive sign hai.

### Precision: 0.6577 (Mean)

**Matlab:** Jab model ne kaha "ye customer churn karega", to **65.77% dafa wo sahi tha**. Yani agar model 100 logon ko "high risk" bole, taqreeban 66 waqai churn karenge, 34 nahi karenge (False Positives).

### Recall: 0.5485 (Mean) — **Ye sabse zaroori number hai**

**Matlab:** Jitne **asal churners** thay train data mein, model ne unme se sirf **54.85% ko pakra**. Baaqi **45%** churners model se **"nikal gaye"** (miss ho gaye) — yaani False Negatives.

**Ye kyun ehem hai?** Yaad hai humne Phase 1 mein discuss kiya tha — **business ke liye False Negative sabse mehenga hai** (customer chala gaya, humein pata hi nahi chala)? Ye number (54.85%) batata hai ke abhi humara model **har 2 mein se 1 churner ko miss kar raha hai** — ye acha nahi hai, aur behtar karna hoga (Phase 6-7 mein).

### F1-Score: 0.5980 (Mean)

Precision aur Recall ka **balance** — ek hi number mein dono ka khayal. Chunke Recall (0.55) Precision (0.66) se kam hai, F1 bhi beech mein kahin (0.60) aa gaya.

---

## Std (Standard Deviation) ka matlab

```
Accuracy Std: 0.0143
```

Ye batata hai ke 5 folds ke **numbers kitne "stable"** hain. Agar Std **bohat kam** ho (jaise yahan 0.014, matlab sirf ~1.4%), to iska matlab model **consistent** hai — har fold mein taqreeban ek jaisa perform kar raha hai, koi fold "ajeeb tarah se acha ya bura" nahi nikla. Ye **achi baat** hai.

Agar Std **bara** hota (jaise 0.15), to matlab model har baar bohat alag perform kar raha hota — jo batata hai model "unstable" hai ya data mein koi masla hai.

## Row 1: Majority Class (sabse bewakoof model)

**Accuracy: 73.46%** — ye model **kuch nahi seekhta**, hamesha "No churn" bol deta hai. Isko hamne pehle bhi discuss kiya tha — sirf isliye high accuracy mil rahi hai kyunke 73.5% log waise hi "No" hote hain.

**Precision, Recall, F1: sab 0.00%** — **ye kyun?** Kyunke ye model **kabhi bhi "Yes" (churn) nahi bolta**. Agar model kabhi "Yes" nahi bolta, to:
- Precision: "jab model ne Yes bola, kitni dafa sahi tha?" — model ne **kabhi Yes bola hi nahi**, is liye ye sawal hi apply nahi hota (0%)
- Recall: "asal churners mein se kitne pakre?" — **zero**, kyunke model ne kisi ko bhi "churn karega" nahi bola

**Matlab:** Ye model **bilkul bekaar** hai asal maqsad ke liye (churners pakadna), chahe uski Accuracy high dikhe. **Yehi is baseline ka poora maqsad tha** — humein dikhana ke Accuracy akeli kitni gumrah kar sakti hai.

## Row 2: Logistic Regression — abhi tak ka behtareen

Humne ye numbers Part 2 mein dekhe thay:
- Accuracy 80.42%, Precision 65.77%, **Recall 54.85%**, F1 59.80%

Ye **sab 4 metrics mein sabse aagay** hai is comparison mein.

---

## Row 3: Decision Tree — yahan ek interesting (aur ehem) baat hai

**Accuracy: 71.32%** — ye to **Majority Class (73.46%) se bhi kam hai!** Yani Decision Tree, "kuch na seekhne wale" model se bhi **bura** perform kar raha hai accuracy mein.

**Ye kyun hua? Yahan ek naya, bohat zaroori concept hai: Overfitting**

**Overfitting ka matlab:** Socho ek bacha imtihaan ki tayyari kar raha hai, lekin wo **samajhne ki bajaye, poora practice paper rata leta hai** — har sawal, har number, bilkul hu-ba-hu yaad kar leta hai. Practice test mein wo **100%** number le aata hai (kyunke usne wahi sawalat rate the).

Lekin jab **asal exam** mein thoray se alag sawalat aate hain, wo **bilkul fail** ho jata hai — kyunke usne **samajha nahi tha, sirf rata tha**.

**Decision Tree yahi karta hai agar usay "control" na kiya jaye:** Wo training data ko itni gehrai se "yaad" kar leta hai (har chhota-mota pattern, chahe wo sirf ittefaq ho) ke jab **naya data** (cross-validation ke "test fold") aata hai, wo confuse ho jata hai — kyunke usne data ke **"asal patterns"** nahi seekhe, sirf **training data ki khaas-khaas tafseelat yaad kar li** thin jo naye data mein repeat nahi hotin.

**Isiliye Decision Tree ka performance kharab aaya** — usne training data ko "ziyada ghor se" seekh liya, jo asal mein uska nuksan ban gaya jab naya (validation) data dikhaya gaya.

---

## Row 4: Random Forest — theek, lekin Logistic Regression se peeche

**Accuracy 78.38%, Recall 48.23%, F1 54.20%**

Random Forest, Decision Tree se **behtar** hai (kyunke ye bohat sare trees ka "average" leta hai, jo overfitting ko kam karta hai — ek akeli tree ki ghalti doosri trees cancel kar deti hain). Lekin phir bhi ye Logistic Regression se **peeche** hai is particular dataset mein.

**Kyun?** Kabhi kabhi simple models (Logistic Regression) un datasets par behtar kaam karte hain jahan data ka rishta **seedha-saadha (linear)** ho. Humare dataset mein shayad features aur churn ka taalluq itna seedha hai ke complex model (Random Forest) ko koi khaas "extra fayda" nahi mila — balke usne bhi thora overfitting kiya (jitna Decision Tree utna nahi, lekin thora).

---

## Sabse zaroori sawal: "Logistic Regression" best kyun hai?

Yaad rakhein — humne decide kiya tha **Recall sabse zaroori hai** (churners ko miss na karna). Is comparison mein:

- Logistic Regression: Recall **54.85%** — sabse zyada
- Random Forest: Recall 48.23%
- Decision Tree: Recall 47.22%
- Majority Class: Recall 0%

**Logistic Regression sab se zyada churners pakad raha hai** (chahe wo 54.85% bhi "acha" number nahi hai — abhi bhi 45% log miss ho rahe hain), isliye abhi ke liye ye **sabse behtar candidate** hai.

---

## Is poori Part 3 ka asal sabaq (sabse zaroori baat)

**Zyada "complex" model (Random Forest, Decision Tree) hamesha behtar nahi hota.** Kai dafa simple model (Logistic Regression) behtar perform karta hai, khaas kar jab:
1. Data ka pattern seedha-saadha ho
2. Complex models "overfit" ho jayen (training data ko bohat zyada "yaad" kar len)

**Isi wajah se hum hamesha multiple models test karte hain** — sirf ye farz nahi kar lete ke "jo model zyada advanced/complicated lagta hai, wo hamesha jeetega."
