Bilkul, chaliye **pytest** ko bilkul shuru se, aasan misalon ke sath samjhata hoon.

## Pehle Yaad Karen: Ab Tak Hum Kaise "Test" Karte Thay

Ab tak jab bhi humein check karna hota tha "kya code sahi kaam kar raha hai," hum **ek script chalatay** (jaise `run_validation.py`), aur **khud aankhon se** output parhte thay — "haan, shape (7043, 21) hai, theek hai."

**Masla:** Ye **manual** hai. Agar kal aap koi cheez badlen (jaise `load_data.py` mein), aapko **phir se** sab scripts chalani parengi, **phir se** khud check karna parega. Ye **thaka dene wala** hai, aur ghalti ka khatra hai (ho sakta hai aap koi cheez check karna **bhool** jayen).

---

## pytest Kya Hai (Asaan Misal)

Socho aap ek factory chala rahe hain jahan **har din** 50 chhotay chhotay checks karne hote hain — jaise "kya bijli chal rahi hai," "kya paani ka pressure theek hai," waghera.

**Manual tareeqa:** Har subah, aap khud jaa kar har cheez check karen — bohat waqt lagta hai.

**pytest ka tareeqa:** Aap **ek dafa** 50 "sensors (automated checks)" laga dete hain. Phir aap **sirf ek button dabatay hain**, aur **sab 50 checks khud-ba-khud ho jati hain**, aur aapko sirf itna batati hain "49 theek hain, 1 mein masla hai, wo ye raha."

**pytest bilkul yehi karta hai code ke liye** — hum ek dafa "checks (tests)" likh dete hain, phir **ek command** (`pytest`) se sab chala kar dekh sakte hain "sab sahi hai ya kahin kuch toot gaya."

## Humne 6 "Checks (Tests)" Kyun Banaye — Har Ek Ko Alag Samjhein

### Test 1 & 2: "Kya data sahi load hota hai?"
```
test_load_raw_data_returns_dataframe
test_load_raw_data_has_expected_shape
```
**Simple check:** "Jab hum `load_raw_data()` chalayen, kya humein asal mein data milta hai (khaali nahi), aur kya uski shape (7043, 21) hai?"

**Misaal:** Jaise koi check kare "jab main bijli ka switch dabaun, kya bulb jalta hai?"

### Test 3: "Kya validation function sahi kaam karta hai achay data par?"
```
test_validate_raw_data_passes_on_clean_data
```
**Check:** "Jab hum achay, saaf data ko `validate_raw_data()` ko den, kya wo **bina kisi error ke** chalta hai, aur sahi result deta hai?"

### Test 4 & 5: "Kya validation function GHALTI pakarta hai agar data kharab ho?"
```
test_validate_raw_data_raises_on_missing_target_column
test_validate_raw_data_raises_on_missing_id_column
```

**Ye sabse dilchasp hain.** Yaad hai Phase 2 mein humne `assert` lagaya tha "agar `Churn` column gayab ho, to code **chillaye (fail ho)**"? Ye tests **jaan boojh kar ek "tootay hue" data (jisme `Churn` column nahi hai) banatay hain**, phir check karte hain **"kya humara code waqai chillaya (error diya), jaisa usay karna chahiye tha?"**

**Misaal:** Jaise aap jaan boojh kar **smoke alarm ke paas dhuwan** le jayen, sirf ye check karne ke liye "kya alarm waqai bajta hai?" Agar na baje, to alarm **kharab** hai — aur humein abhi pata chal gaya, baad mein nahi (jab asal aag lage).

### Test 6: "Kya Churn column sirf Yes/No rakhta hai?"
```
test_churn_column_only_has_expected_values
```
**Check:** Yaad hai Phase 2 mein humne ye manual check kiya tha? Ab ye **hamesha ke liye automated** ho gaya.

## Output Ko Kaise Parhein

```
tests/test_data.py::test_load_raw_data_returns_dataframe PASSED          [ 16%]
```

- **`tests/test_data.py::test_load_raw_data_returns_dataframe`** — ye batata hai kaunsi file, kaunsa test
- **`PASSED`** — ye test **kamyab** hua (jaisa expect kiya tha)
- **`[16%]`** — progress bar, "16% tests ho chukay hain abhi tak"

**Aakhir mein:**
```
============================== 6 passed in 0.80s ==============================
```
**Sab 6 tests, 0.80 second mein, sab PASSED** — matlab **humara poora data-loading aur validation system theek kaam kar raha hai.**

## Agar Koi Test "FAIL" Hota To Kya Hota?

Agar, misaal ke taur par, kisi ne `load_data.py` mein galti se kuch badal diya hota (jaise column ka naam), to output kuch aisa dikhta:

```
tests/test_data.py::test_load_raw_data_has_expected_shape FAILED
```

Aur neeche **exact batata** "expected (7043, 21), got (7043, 20)" — taake **turant** pata chal jaye kahan masla hai, bina khud dhoondhne ke.
