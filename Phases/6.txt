## 4 Naye Hints (Features)

### 1. "is_new_customer" — Kya ye naya customer hai?
Socho ek banda sirf 2-3 mahine se company ka customer hai. Hum keh dete hain: **"Haan, ye naya hai"** (1). Agar bohat purana hai (jaise 3 saal se), to **"nahi, naya nahi"** (0).

**Kyun banaya?** Kyunke humne pehle dekha tha naye log jaldi chhor dete hain.

### 2. "high_risk_contract" — Kya ye bohat khatarnak combination hai?
Socho ek banda **naya bhi hai AUR** uska contract bhi "jab chahe chhor do" (Month-to-month) type ka hai. Dono cheezein mil kar usay **"bohat zyada khatray mein"** bana deti hain — hum usay **1** mark karte hain. Agar dono baatein sach nahi, to **0**.

**Kyun banaya?** Do khatarnak cheezein mil kar aur zyada khatarnak ban jati hain.

### 3. "avg_monthly_spend_ratio" — Kya bill achanak barh gaya?
Socho customer ka bill **pehle kam tha**, lekin **ab achanak zyada** ho gaya hai. Ye jaise koi "jhatka (shock)" hai usay. Hum ye number nikalte hain: "ab ka bill, purane average se kitna zyada hai."

**Kyun banaya?** Agar bill achanak barh jaye, log pareshan ho kar chhor dete hain.

### 4. "num_services" — Kitni cheezein li hain customer ne?
Socho customer ne sirf internet liya, ya internet + phone + TV + security sab kuch liya. Hum **sirf ginti karte hain** — kitni services customer ke paas hain.

**Kyun banaya?** Jisne zyada cheezein li hain, wo company se zyada "juda hua" hai, aasani se nahi chhorega.

**Misaal:** Agar aap kisi dost ko test mein madad karna chahte hain, aap usay poora kitaab nahi dete, balke **important lines highlight** kar dete hain. Feature Engineering wahi hai — humne data mein se **important cheezein highlight** kar di hain, taake model ko jaldi samajh aaye.

# File 1: `preprocessing.py` mein `engineer_features()` function

```python
def engineer_features(df: pd.DataFrame) -> pd.DataFrame:
```
Ye function **poora raw DataFrame** leta hai, aur **naye columns ke sath** wapas deta hai.

```python
    df = df.copy()
```
Wahi safety step jo humne har jagah dekha — asal data ko chhoo na kar, ek **copy** par kaam karte hain.

```python
    df = clean_totalcharges(df)
```
**Bohat zaroori line.** `avg_monthly_spend_ratio` banane ke liye humein `TotalCharges` ko **number** ki shakal mein chahiye (text nahi), isliye pehle wahi **purana function (Phase 4 mein banaya tha)** dobara istemal kiya — **dobara code likhne ki zaroorat nahi padi**, ye wahi "reusability" wala faida hai.

### Feature 1: `is_new_customer`
```python
    df["is_new_customer"] = (df["tenure"] < 6).astype(int)
```
- `df["tenure"] < 6` — har row ke liye check karta hai "kya tenure 6 se kam hai?" — natija True ya False
- `.astype(int)` — True ko `1`, False ko `0` mein badal deta hai

### Feature 2: `high_risk_contract`
```python
    df["high_risk_contract"] = (
        (df["Contract"] == "Month-to-month") & (df["tenure"] < 12)
    ).astype(int)
```
- `(df["Contract"] == "Month-to-month")` — "kya contract Month-to-month hai?" (True/False)
- `&` — Python mein ye **"AND"** ka matlab hai — **dono shartein sach honi chahiye**
- `(df["tenure"] < 12)` — "kya tenure 12 se kam hai?"
- Dono ko `&` se jor kar, phir `.astype(int)` se 0/1 banaya

**Agar sirf ek shart sach ho (jaise sirf Month-to-month, lekin tenure 20 mahine), to pura result False/0 hoga — kyunke `&` ko dono shartein chahiye.**

### Feature 3: `avg_monthly_spend_ratio`
```python
    df["avg_monthly_spend_ratio"] = df["MonthlyCharges"] / (
        df["TotalCharges"] / (df["tenure"] + 1) + 0.01
    )
```
Ye thora pechida lagta hai, chaliye tod kar dekhein:

- `df["TotalCharges"] / (df["tenure"] + 1)` — ye "purana average monthly bill" nikal raha hai (total bill ko mahinon se taqseem kar ke)
- `+ 1` tenure mein — agar koi customer bilkul naya hai (`tenure=0`), to **0 se taqseem (divide by zero)** nahi ho sakti, isliye hum hamesha **+1** karte hain safety ke liye
- `+ 0.01` — isi tarah, agar average bill bilkul 0 ho, to phir bhi divide by zero na ho
- `df["MonthlyCharges"] / (...)` — ab **ab ka bill** ko **purane average** se taqseem kiya — agar ye number **1 se zyada** hai, matlab ab ka bill purane se zyada hai (barh gaya)

### Feature 4: `num_services`
```python
    service_columns = ["OnlineSecurity", "OnlineBackup", ...]
    df["num_services"] = (
        df[service_columns].apply(lambda x: (x == "Yes").sum(), axis=1) +
        (df["InternetService"] != "No").astype(int)
    )
```
- `df[service_columns].apply(lambda x: (x == "Yes").sum(), axis=1)` — har row ke liye, in 7 columns mein se kitne "Yes" hain, unhein gin raha hai (`axis=1` ka matlab "har row ke liye", column ke liye nahi)
- `(df["InternetService"] != "No").astype(int)` — agar InternetService "No" nahi hai (yani kisi tarah ka internet hai), to +1 extra add karo
- Dono ko `+` se jor diya — final total services count

```python
    return df
```
Poora DataFrame, 4 naye columns ke sath, wapas bhej diya.

```python
print(df_engineered[numeric_features].describe().loc[["mean", "min", "max"]].to_string())
```
`.describe()` pandas ka ek built-in function hai jo **mean, min, max, aur bohat kuch** deta hai ek dafa mein. `.loc[["mean", "min", "max"]]` sirf humein chahiye wale 3 rows chun leta hai (baaqi, jaise std, 25%, 75%, chhor diye).

```python
churn_by_new = df_engineered.groupby("is_new_customer")["Churn"].apply(
    lambda x: (x == "Yes").mean() * 100
)
```
Ye **sabse important line** hai, chaliye tod kar samjhein:

- `.groupby("is_new_customer")` — customers ko **2 groups** mein baant do (0 wale, 1 wale)
- `["Churn"]` — har group mein se sirf `Churn` column dekho
- `.apply(lambda x: (x == "Yes").mean() * 100)` — har group ke liye: "kitne % log Churn='Yes' hain?" — `(x == "Yes")` True/False deta hai, `.mean()` average nikalta hai (jo automatically percentage jaisa number deta hai), `* 100` se ye asal percentage ban jata hai

**Natija:** `churn_by_new[0]` = group 0 ka churn %, `churn_by_new[1]` = group 1 ka churn %.

```python
df_engineered["spend_ratio_tertile"] = pd.qcut(
    df_engineered["avg_monthly_spend_ratio"],
    q=3,
    labels=["Low", "Medium", "High"]
)
```
Yaad hai humne "tertiles" (3 barabar groups) ka zikr kiya tha? `pd.qcut(..., q=3)` ye **automatically** karta hai — sab customers ko unke `avg_monthly_spend_ratio` ke hisab se tarteeb de kar, **3 barabar hisson** mein baant deta hai, aur har hissay ko "Low"/"Medium"/"High" label de deta hai.

```python
churn_by_services = df_engineered.groupby("num_services")["Churn"].apply(
    lambda x: (x == "Yes").mean() * 100
)
for services in sorted(df_engineered["num_services"].unique()):
    count = (df_engineered["num_services"] == services).sum()
    print(f"{services} services: {churn_by_services[services]:.2f}% (n={count})")
```
`num_services` pehle se hi ek number (1 se 8) hai, isliye yahan har **ginti (1, 2, 3...8) apna alag group** ban jata hai — `groupby` isay khud samajh leta hai.

## Misaal se samjhen

Socho aap ek factory chala rahe hain jo customers ka data leti hai aur "churn hoga ya nahi" predict karti hai.

**Abhi tak factory ye karti thi:**
```
Raw customer data → Saaf/Taiyar karo → Model se predict karo
```

**Ab humein factory mein ek NAYA machine add karna hai, bilkul shuru mein:**
```
Raw customer data → [NAYA: 4 hints banao] → Saaf/Taiyar karo → Model se predict karo
```

Is "naye machine" ka kaam hai: raw data dekh kar, khud-ba-khud ye 4 cheezein calculate kar dena — "kya ye naya customer hai?", "kya khatarnak combo hai?", waghera — taake model ko ye extra, "smart" information bhi mil sake.

## Ye kyun hua? (Asal sabaq)

Yaad rakhein — humne EDA mein dekha tha ye features **individually** (akele) churn se bohat zyada juday hue hain (34-45% farq). **Lekin ye sach hona ek alag baat hai, aur model ke liye "nayi, faida mand information" dena ek alag baat hai.**

**Misaal se samjhein:** Socho aap ek doctor ko patient ki file de rahe hain. File mein already likha hai "Umar: 65 saal." Agar aap ek **naya column** bhi add karen jisme likha ho "Senior Citizen: Yes" — ye **bilkul sach** hai, aur agar aap akela ye column dekhen, "Senior Citizen = Yes" wale logon mein zyada bimari milegi. Lekin **doctor ko pehle hi "Umar: 65" se pata chal gaya tha ke ye senior hai** — naya column usay **koi extra cheez nahi bata raha**, sirf wahi baat dohra raha hai.

`Logistic Regression` ek **"smart" model** hai jo khud hi `tenure` aur `Contract` jaisay raw numbers se ye patterns nikal leta hai — usay humara "pehle se chaba kar diya hua" hint (`is_new_customer`) chahiye hi nahi tha. Balke, extra columns ne thori "noise" (confusion) add kar di, jisse performance thora **kam** ho gaya.
